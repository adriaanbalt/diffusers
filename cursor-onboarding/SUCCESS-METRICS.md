# Success Metrics — Measuring Onboarding Impact

**Audience:** SA, platform lead, PM, engineering leadership  
**Use:** Baseline before lighthouse; review at 30/60/90 days

---

## North star

**Time to first merged PR** for engineers onboarded after rules deployment vs historical baseline.

---

## Primary metrics

| Metric | Definition | How to measure | Target (90 days) |
|--------|------------|----------------|------------------|
| **Time to first merged PR** | Days from start date → first merge to main | GitHub / Linear | ↓ 30–50% vs baseline |
| **Convention review comments** | PR comments tagged file-placement, naming, imports, test structure | GitHub PR review export | ↓ 50% by engineer's 3rd PR |
| **CI pass rate (first push)** | % of first commits that pass CI without fix-up | GitHub Actions | ↑ toward team average within 30 days |
| **Review cycles to merge** | Review rounds before merge (first 3 PRs) | GitHub | ↓ vs pre-rules cohort |

---

## Secondary metrics

| Metric | Definition | Signal |
|--------|------------|--------|
| Cursor rule engagement | Engineers using Agent in repo (if telemetry available) | Adoption |
| ONBOARDING.md views | Wiki/docs analytics | Self-serve usage |
| Platform team intervention rate | % of first PRs requiring platform lead unblock | Rules working vs gaps |
| Rule PR frequency | How often team updates `.cursor/rules/` | Healthy ownership |
| Engineer confidence survey | 1–5: "I knew where to put files" post-week-2 | Qualitative validation |

---

## Baseline capture (Phase 0)

Before installing rules, record for last 5–10 joiners:

```
Engineer | Start date | First PR opened | First merge | Review comments (conv.) | CI fails (first push)
```

If no historical data: use lighthouse squad as cohort zero; compare to next cohort at 90 days.

---

## Reporting cadence

| When | Audience | Content |
|------|----------|---------|
| Week 2 | Platform lead | Lighthouse retro — qualitative |
| Day 30 | Eng manager | CI pass rate, first PR timing |
| Day 90 | VP / director | Full dashboard + executive summary update |
| Quarterly | SA + customer | Expansion decision, rule pruning |

---

## Executive narrative template

> "Since deploying Cursor onboarding rules [date], new engineers reaching first merged PR in **[X] days** vs **[Y] days** baseline. Convention-related review comments down **[Z]%** by the third PR. Platform team spend on first-PR unblocking down **[W] hours/month**."

Calibrate X/Y/Z/W in discovery — never present fabricated numbers in a customer meeting.

---

## What not to measure (yet)

- Lines of code generated by AI
- Raw Cursor usage hours (activity ≠ outcome)
- Rule count (more rules ≠ better)

---

## Interview talking point

> "I'd baseline time-to-first-PR before we install anything. At 90 days we read convention comment rate and CI pass rate — if those move, leadership sees ROI without me claiming 'AI magic.'"
